NeonWrt systemd PID 1 conversion
================================

Changes in this package:

* base-files depends on systemd.
* /sbin/init is created as a symlink to /usr/lib/systemd/systemd.
* /var is a real directory instead of the OpenWrt /var -> /tmp symlink.
* /var/run -> /run and /var/lock -> /run/lock.
* /etc/init.d/boot no longer creates the incompatible /run -> /var/run link.
* pi_init_cmd is set to /usr/lib/systemd/systemd for preinit/fallback users.

IMPORTANT
---------
Do not modify files/lib/preinit/99_10_run_init to start systemd.  In normal
OpenWrt, preinit is launched by procd as a child, so starting systemd there
would NOT make systemd PID 1.  systemd must be started by the kernel as PID 1
through /sbin/init (or temporarily with kernel cmdline init=...).

The standard procd package and neon-procd compatibility package MUST NOT
install /sbin/init.  neon-procd should run as a normal daemon/service under
systemd.

After the complete rootfs/image is assembled, verify:

  readlink staging_dir/target-aarch64_cortex-a72_glibc/root-bcm27xx/sbin/init

Expected:

  /usr/lib/systemd/systemd

Then locate any package that still owns/creates init:

  grep -R "sbin/init" -n package feeds 2>/dev/null

If the flashed image still prints:

  procd: - early -
  procd: - ubus -
  procd: - init -

then /sbin/init has still been supplied/overwritten by procd in the FINAL
rootfs.  As a one-boot diagnostic, append:

  init=/usr/lib/systemd/systemd

to the kernel command line.  If systemd then starts, the remaining fault is
final-rootfs init ownership, not the systemd binary itself.
