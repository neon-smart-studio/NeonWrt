# neon-procd 0.2.0

OpenWrt `procd` compatibility layer for NeonWrt with **systemd as PID 1**.

## v0.2 architecture

```
/etc/init.d/foo (USE_PROCD=1)
        |
/lib/functions/procd.sh
        |
        +---- ubus call service set/list/delete/signal/event
        |                 |
        |          neon-procd-ubus
        |                 |
        +-----------------+
                          |
                    neon-procd
                          |
              systemd-run / systemctl
                          |
                       systemd
```

`neon-procd-ubus` owns the OpenWrt-compatible `service` ubus object. Service definitions are persisted under `/run/neon-procd/services/` so `ubus call service list` can expose instance `running` state while systemd remains the actual process manager.

## Implemented

- procd service/instance creation
- command, env, user/group, nice, limits, no_new_privs
- respawn -> systemd Restart/StartLimit
- named/multiple instances
- delete/kill, signal, running/status
- ubus `service set`, `list`, `delete`, `signal`, `event`
- `config.change` reload triggers
- interface trigger matching (`interface.*` plus interface equality)
- raw trigger execution (basic immediate semantics)
- OpenWrt `/etc/rc.d/S*` boot bridge

The trigger JSON generated by `procd.sh` follows the upstream procd shape instead of the simplified v0.1 records.

## Still incomplete

- trigger debounce/timeout semantics are not identical to upstream procd
- `file`, `data`, `netdev`, `watch`, `watchdog` change monitoring
- ujail/jail mount translation
- seccomp and capability JSON translation
- pidfile/forking daemon semantics
- ubus `service list` verbose metadata is intentionally smaller than upstream
- watchdog/hotplug/inittab responsibilities that belong to PID 1 are not reimplemented; systemd should own those

## Install

Copy the directory to:

```
package/system/neon-procd/
```

Enable:

```
CONFIG_PACKAGE_systemd=y
CONFIG_PACKAGE_neon-procd=y
```

Build:

```
make package/neon-procd/{clean,compile} V=s
```

Do not install upstream procd's `/lib/functions/procd.sh` over this package.

## Runtime checks

```
systemctl status neon-procd-ubus
ubus list service
ubus call service list
```

Then test a normal `USE_PROCD=1` service:

```
/etc/init.d/minidlna start
ubus call service list '{"name":"minidlna"}'
systemctl status 'neon-procd-minidlna-*'
```

For a UCI reload trigger:

```
ubus call service event '{"type":"config.change","data":{"package":"minidlna"}}'
```

## Integration rule

Do not run upstream procd as a second service manager. In NeonWrt the intended ownership is:

- systemd: PID 1, lifecycle, cgroups, restart, logging
- ubusd: ubus transport
- neon-procd-ubus: `service` ubus compatibility object
- neon-procd: translation to systemd
- UCI/LuCI/OpenWrt packages: unchanged compatibility-facing API
